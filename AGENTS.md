# Suspender: notes for coding agents

A Herdr App mod written in TypeScript, compiled to plain JavaScript. It puts Claude Code and Codex sessions to
sleep and resumes them in the same tab. Users who only want to install it should read `README.md` and
`RECIPE.md` instead.

## Build and check

```
pnpm install
pnpm check
```

`pnpm check` runs Biome, `tsc --noEmit` on the sources and the tests, `node --test`, a fresh build compared with
the committed `mods/suspender/`, a check that the copy in `layout/` matches it, and a privacy scan. Run one test
file with `node --test test/<file>.test.ts`. `pnpm build` writes `mods/suspender/` and refreshes `layout/`; commit
both after changing `src/`. After a change to anything that draws, also run `herdr-app check mods/suspender`
(Herdr writes `*.d.ts` and `jsconfig.json` next to the mod; they are ignored by git and safe to delete).

Node 22.18 or newer, pnpm 12. The code uses only erasable TypeScript syntax (no enums or namespaces) and `.ts`
import specifiers, so tests run on the sources directly. There are no runtime dependencies, and none should be
added: Herdr runs a single folder of JavaScript.

## Folders

- `src/core/`: pure logic (state machine, store format, paths, text fitting, layout generator). No import of
  `herdr` or `gpui-kit`.
- `src/adapters/`: one file per agent behind the `AgentAdapter` contract (`contract.ts`), registered in
  `index.ts`. Adapters reach the system only through `Ports`.
- `src/platform/`: `Ports` (files, processes, `hc`) and per-OS process code.
- `src/runtime/`: the engine that binds sessions to terminals and carries out sleep and wake.
- `src/ui/`: the views (strip, panel, popup, pill, toggle). Colors come from the theme only.
- `src/i18n/`: all user-facing text in `en.ts`, read through `t(key, params)`.
- `mods/suspender/`: the compiled mod plus `mod.json` and icons. Never edit the `.js` files by hand.
- `layout/`: the second catalog card (a layout and a copy of the mod), generated by `pnpm build`.
- `test/`: tests, with in-memory ports (`fakePorts.ts`) and synthetic data only.
- `scripts/`: build helpers and the privacy check. `docs/`: architecture and decision records.

## Releasing

The update button installs a release from its tag and checks every file against `mods/suspender/manifest.json`
at that tag (ADR 12), so a release is:

1. Set the version in `package.json` and `src/core/release.ts` (`MOD_VERSION`), move `[Unreleased]` in
   `CHANGELOG.md` under the version, then `pnpm build` (it rewrites the manifest with the new version) and
   `pnpm check` (it fails if the manifest, the version or the build is stale).
2. Commit (`🔖 chore(release): X.Y.Z`), tag `vX.Y.Z` on that commit and push the commit and the tag.
3. Publish a GitHub release for the tag, not a draft or a pre-release: the mod asks
   `/releases/latest`, which shows only published ones. Its notes are what What's new opens.

Nothing is uploaded besides the tag: the manifest and the files are read raw from it. A tag whose manifest does
not match its files makes every update cancel with "checksum mismatch".

## Rules that are easy to break

- Test through the public interface and watch a new test fail for the right reason before writing the code.
- Do not put real paths, project names, transcripts or addresses into code, tests, fixtures or docs. Fixtures
  are made up. `node scripts/check-privacy.ts --history` checks every commit.
- Do not use timers for animation (native `.transition`, `.loop`, `.spin` only) and do not start processes in
  frequent paths; see `docs/architecture.md` for the cost rules.
- Keep the layout generator working on block ids, never on positions.
- Commits: conventional commits with a gitmoji, in English, subject up to about 70 characters.
